# Offline test suites

Nine suites cover the protocol and installer logic without a live Claude Code / Codex session. Sandboxes live in `%TEMP%\press-1-tests\` — the repo tree is never written to.

| Suite | What it covers | Run |
|-------|----------------|-----|

Notes:

- The AHK harness `#Include`s the real `press-1.ahk` and then redirects its directories to the sandbox — run it from the repo so the relative include resolves. It exercises parsing/lifecycle functions only; no popups are shown.
- The hook suites spawn the real `permission-request.js` / `codex-permission-request.js` as a child with an isolated `TEMP` (stdin payload → stdout decision). Decision-route permission cases block until the suite writes a decision file; exact auto-review bypasses, proxy-mute, off, and native-control cases intentionally exit early.
- `codex-merge.test.js` never calls a live Codex installation: pure helpers run directly, while the trust handshake uses a scripted fake `codex app-server` — no Codex CLI needed.
- `codex-native-control-smoke.ps1` is a **manual live smoke helper** for the opt-in Codex panel native-control path. Run it, trigger a real approval in the Codex VS Code panel, press `Ctrl+Win+1/2/3`, then press Enter in the helper console; it logs whether a `native_control:true` pending appeared, whether it had no `decision_file`, whether the hook released, and whether the pending disappeared after the confirmed hotkey step. Use `-NoPrompt` only for syntax/fail-path checks.
- Before releasing a change to the version-sensitive reviewer route, run this live matrix on **new turns** (steering an existing turn does not change its reviewer): (1) exact auto-review on both a fresh and a resumed Native Desktop thread (the latter must carry `\\?\X:\...`) and on at least one non-Desktop standard hook surface → no sound/popup, while `Ctrl+Win+D` reports `auto_pass / exact_auto_review`; (2) `Ask for approval` / reviewer `user` on a standard route → press-1 appears and answers; (3) uncheck **Codex → Let Auto-review decide (experimental)**, start a new auto-review turn → popup appears; (4) restore the check and start one more new turn → silent auto-review returns; (5) with the panel proxy enabled, an auto-resolved action creates no popup, while a real post-review manual request appears in both the native panel and press-1 without running or replacing the transcript-probe status.
- `gdip-smoke.ahk` is a separate **runtime** renderer smoke (not in the table above): it drives the real GDI+ stack — builds a 3-card stack, moves the active ring, toggles a card's expand (rebuild at a taller height), dismisses, and re-shows — catching runtime errors the syntax-only harness can't. PASS/FAIL is written to `%TEMP%\press-1-tests\gdip-smoke.txt`; it briefly shows real cards bottom-right (~2 s). Run: `& "C:\Program Files\AutoHotkey\v2\AutoHotkey64.exe" tests\gdip-smoke.ahk`.
- Run all nine (plus the gdip smoke) after any change to `permission-request.js`, `codex-permission-request.js`, `session-teardown.js`, `press-1.ahk`, `install.ps1`, `merge-hooks.js`, `merge-codex-hooks.js`, `codex-mitm.js`, or `codex-proxy-settings.js`.
